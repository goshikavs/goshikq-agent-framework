# Owner commands: publish v1.0.0-rc.1

Do **not** run these until the owner explicitly approves a public RC tag and GitHub prerelease.

These commands do not publish crates.io, PyPI, or npm. Registry publication needs a second, separate authorization.

Assume `COMMIT` is the validated release-candidate SHA (see `docs/release/v1.0-artifact-manifest.md`).

```bash
git fetch origin
git checkout release/v1.0-hardening
git rev-parse HEAD   # must equal COMMIT
git tag -a v1.0.0-rc.1 "$COMMIT" -m "Goshikq v1.0.0-rc.1"
git push origin v1.0.0-rc.1
```

Download the native archives, SHA256SUMS, and SBOM from the matching GitHub Actions run (release-candidate workflow). Verify checksums after download:

```bash
sha256sum -c SHA256SUMS
```

Create a **prerelease** (not latest stable):

```bash
gh release create v1.0.0-rc.1 \
  --prerelease \
  --title "v1.0.0-rc.1" \
  --notes-file docs/release/v1.0-release-notes.md \
  goshikq-1.0.0-rc.1-linux-amd64.tar.gz \
  goshikq-1.0.0-rc.1-linux-arm64.tar.gz \
  goshikq-1.0.0-rc.1-windows-amd64.zip \
  goshikq-1.0.0-rc.1-macos-amd64.tar.gz \
  goshikq-1.0.0-rc.1-macos-arm64.tar.gz \
  SHA256SUMS \
  goshikq.spdx.json
```

Include `goshikq-1.0.0-rc.1-windows-arm64.zip` only if that experimental artifact smoked successfully on `windows-11-arm`.

Python / npm / crates.io remain unpublished until a separate owner decision.

Stable `v1.0.0` is a different approval. Do not retitle this prerelease as latest stable.
