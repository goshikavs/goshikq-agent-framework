# Authentication regression — v1.0.0-rc.2

OIDC lives in `crates/goshikq-server/src/oidc.rs`. Production path: JWKS + RS256 (also RS384/512, ES256/384, PS256/384/512). HMAC is loopback-only.

## Vulnerability

GHSA-h395-gr6q-cpjc / CVE-2026-25537: jsonwebtoken versions before 10.3.0 treated a failed parse of `exp`/`nbf` like “claim absent”. A string `nbf` with `validate_nbf = true` could skip the not-before check.

Goshikq 9.3.1 set `validate_nbf = true` without putting `nbf` in `required_spec_claims`. That path was reachable for JWTs that still deserialized into `OidcClaims` (or failed only after library validation).

## Remediation

- `jsonwebtoken` **12.0.0** (GHSA patch floor 10.3.0; 12 also patches remaining `sub`/`iss`/`aud` type confusion) with features `use_pem`, `rust_crypto`
- `set_required_spec_claims(["exp", "iss", "aud", "sub"])`
- `validate_exp`, `validate_nbf`, `validate_aud` remain on
- Reject empty `sub` and missing `exp` after decode
- Lockfile gate: `scripts/assert_jsonwebtoken_patched.py`

Preserved: JWKS fetch, unknown-`kid` refresh, issuer, audience, algorithm allow-list, HMAC rejection in JWKS mode, membership/RBAC, project header isolation.
