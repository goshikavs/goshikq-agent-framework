Future SDK order if there is demand: Go (small HTTP client), then C#, then Java/Kotlin. Each needs a maintainer, a clean consumer test, and a compatibility promise. None of them are part of v1.0.1.

## Trusted publishing

`.github/workflows/publish-python.yml` and `publish-npm.yml` run only on `workflow_dispatch` when the input is exactly `PUBLISH` and the selected tag's package version is `1.0.1` or newer and matches the tag. They request OIDC (`id-token: write`) and a protected environment. They do not contain registry tokens. They do not run on push to `main`.

Do not run them until the owner says to publish.

## Rust crates

`goshikq-protocol` is the closest thing to a reusable API and is still a workspace crate: it has no `crates.io` version line independent of the monorepo, its docs are internal, and the server, storage, and runtime crates are not a stable library surface. Recommendation: keep installing Rust users from the GitHub Release. Revisit a single `goshikq-protocol` crate only with a published SemVer policy and an external `cargo new` compile test.
