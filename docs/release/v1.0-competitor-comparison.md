# Evidence-based comparison (architecture, not benchmarks)

Goshikq does not publish numbers against Temporal, DBOS, Restate, LangGraph, or Pydantic AI. Those products can implement similar *policies* in application code. The difference claimed here is **what is first-class in the runtime**, not “competitors cannot.”

| Concern | Goshikq (in tree) | Others (typical) |
| --- | --- | --- |
| Native outcome verification | Goal predicates on `StateSnapshot`; tool SUCCEEDED ≠ VERIFIED | Workflow success often means activity completion; verification is app-level |
| Evidence freshness | Versioned evidence, change-impact, stale approval invalidation | Usually custom |
| Durable execution | Checkpoints, action journal, leases, crash harness | Temporal/DBOS/Restate are mature durable engines; Goshikq is narrower and younger |
| Human approval | Runtime gate + Studio queue with revalidation | Temporal signals / custom UIs |
| Multi-agent | Parent/child runs; child COMPLETED ≠ parent VERIFIED | LangGraph / custom graphs |
| Retry safety | Effect categories + idempotency keys | Activities + idempotency in user code |
| SDK interop | Python + TypeScript workers on one Rust runtime | Language SDKs vary |
| Security | OIDC/JWKS, API keys, RBAC, project isolation | Production systems vary; Goshikq is not certified |
| Deployment | Single `goshikq-server` + Postgres | Temporal cluster, Restate, etc. are different operational models |
| Developer experience | Studio explorer, mock model, examples | Mature docs and ecosystems |

Pydantic AI is a Python agent SDK, not a durable runtime. LangGraph is a graph runtime; inbound traces into Goshikq stay UNVERIFIED.
