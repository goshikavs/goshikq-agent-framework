# External developer testing guide — v1.0.0-rc.1

This guide is for people who are **not** in the Goshikq authoring tree. It uses the public GitHub **prerelease**, not PyPI/npm/crates.io.

Prerelease: https://github.com/goshikavs/goshikq-agent-framework/releases/tag/v1.0.0-rc.1  
Binaries: commit `1f4d35dd6b73801ede2ec1e64ad906645c4d7a60`  
Bug reports: https://github.com/goshikavs/goshikq-agent-framework/issues/new?template=bug_report.md

This is **not** stable v1.0. Windows ARM64 is experimental. Do not put secrets in issues.

## 1. Checksums

Download `SHA256SUMS` and the archive for your platform from the prerelease page.

```bash
sha256sum -c SHA256SUMS
```

Windows (PowerShell):

```powershell
Get-FileHash -Algorithm SHA256 goshikq-1.0.0-rc.1-windows-amd64.zip
```

Compare the hex digest to the matching line in `SHA256SUMS`. Stop if it does not match.

| Platform | File |
| --- | --- |
| Linux AMD64 | `goshikq-1.0.0-rc.1-linux-amd64.tar.gz` |
| Linux ARM64 | `goshikq-1.0.0-rc.1-linux-arm64.tar.gz` |
| macOS Intel | `goshikq-1.0.0-rc.1-macos-amd64.tar.gz` |
| macOS Apple Silicon | `goshikq-1.0.0-rc.1-macos-arm64.tar.gz` |
| Windows AMD64 | `goshikq-1.0.0-rc.1-windows-amd64.zip` |
| Windows ARM64 | `goshikq-1.0.0-rc.1-windows-arm64.zip` (**experimental**) |

## 2. Start the runtime from the archive

Unix:

```sh
tar -xzf goshikq-1.0.0-rc.1-linux-amd64.tar.gz
cd goshikq-1.0.0-rc.1-linux-amd64
chmod +x goshikq-server goshikq
export DATABASE_URL=embedded
export GOSHIKQ_AUTH_MODE=none   # development only
./goshikq-server
```

Windows (cmd), AMD64:

```bat
tar -xf goshikq-1.0.0-rc.1-windows-amd64.zip
cd goshikq-1.0.0-rc.1-windows-amd64
set DATABASE_URL=embedded
set GOSHIKQ_AUTH_MODE=none
goshikq-server.exe
```

First `DATABASE_URL=embedded` start downloads Theseus PostgreSQL from GitHub. If GitHub rate-limits you, set `GITHUB_TOKEN` to a **personal fine-grained token with public-repo read** (never commit it). Production must use a real Postgres `DATABASE_URL` and must not use `GOSHIKQ_AUTH_MODE=none`.

Health:

```sh
curl -fsS http://127.0.0.1:7400/health
curl -fsS http://127.0.0.1:7400/ready
./goshikq --version
```

Expect HTTP 200 and a version string containing `1.0.0-rc.1`.

## 3. Clone source for SDKs (not on registries)

Keep the runtime from step 2 running. In another directory:

```bash
git clone https://github.com/goshikavs/goshikq-agent-framework.git
cd goshikq-agent-framework
git checkout v1.0.0-rc.1
cp .env.example .env
```

Python:

```bash
python -m pip install -e sdk/python
python -c "import goshikq_ai; print(goshikq_ai.__version__)"
```

Expect `1.0.0rc1`. There is no `pip install goshikq-ai` from PyPI.

TypeScript (Bun 1.4+):

```bash
bun install
bun --filter @goshikq/sdk test
```

`@goshikq/sdk@1.0.0-rc.1` is not on npm.

## 4. Hello-agent (mock model)

```bash
python examples/hello-agent/main.py
```

Expect `status: COMPLETED` and `verification: VERIFIED`. If the model only *says* Ada was greeted and never calls `record_greeting`, verification must not pass.

Optional Studio:

```bash
cd apps/studio && bun install && bun run dev
```

Open `http://127.0.0.1:3000` → Executions → hello-agent → Verification **VERIFIED**.

TypeScript equivalent:

```bash
goshikq run examples/typescript-refund-agent
```

Happy path: `COMPLETED` / `VERIFIED`.

## 5. Delayed external-state verification

```bash
python examples/retail-refund/main.py
python examples/retail-refund/main.py --fault never_settles
```

| Command | Expected |
| --- | --- |
| `python examples/retail-refund/main.py` | `VERIFIED` (store `refunded` + `settled`, not merely processor `accepted`) |
| `--fault never_settles` | `UNVERIFIED` / `INCONCLUSIVE`, not a fake success |

TypeScript: `GOSHIKQ_REFUND_FAULT=never_settles bun --cwd examples/typescript-refund-agent start`

## 6. Human approval and stale evidence

```bash
python examples/insurance-claims/main.py
```

The run should enter `WAITING_FOR_APPROVAL` for `authorize_payout`. Approve in Studio `/approvals` or deny. A model sentence is not a paid claim.

Stale policy:

```bash
python examples/insurance-claims/main.py --mutate-policy
```

Policy POL-1 v4→v5 while approval is pending must **invalidate** the old approval. Payout must not dispatch on the stale version.

## 7. Crash / restart recovery

With the packaged server still using the same data directory (embedded Theseus under `.goshikq/postgres` or your `DATABASE_URL`):

1. Start `python examples/insurance-claims/main.py` until `WAITING_FOR_APPROVAL`.
2. Stop `goshikq-server` (Ctrl+C). On Windows, if `/ready` still binds, also stop leftover `postgres` listeners on the embedded port.
3. Start `goshikq-server` again with the **same** `DATABASE_URL`.
4. `GET /ready` returns 200. The approval run is still present.
5. Approve. The original payout invocation is reused; a second payout row is not created.

Automated harness (needs Postgres + a server binary on `PATH` or `GOSHIKQ_SERVER_BIN`):

```bash
python -m pytest tests/crash/test_crash_boundaries.py -v
```

Crash-recovery **latency** tables are **NOT_RUN** in this RC. Do not invent numbers.

## 8. Known release-candidate limitations

- Not stable v1.0. Not SOC 2 / HIPAA / PCI.
- No PyPI, npm, or crates.io packages.
- Windows ARM64 is experimental (`continue-on-error` in CI).
- Hosted IdP (Entra / Keycloak / Auth0) is not certified.
- Live LLM tests are skipped unless you set `GOSHIKQ_LIVE_LLM=1` with your own keys. Do not send those keys to Goshikq maintainers.
- Performance vs Temporal / DBOS / Restate / LangGraph is **not** claimed.
- `GOSHIKQ_AUTH_MODE=none` is for local testing only.
